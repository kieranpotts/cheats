= Compaction

Pi automatically summarizes older context to keep long sessions within the model's context window. This is a core feature, not an extension.

== How it works

1. Walks backwards through the messages until it reaches the `keepRecentTokens` threshold (default 20,000) - this is the cut point.
2. Extracts the messages from the previous boundary up to the cut point.
3. Generates a structured summary via the LLM, folding in any previous summary for continuity.
4. Saves a `CompactionEntry` (summary + metadata) into the session.
5. Reloads the session from the summary plus the recent messages.

Complete turns are preserved where possible. If a single turn is larger than the budget, Pi creates a "split turn", summarizing the turn's prefix and the history separately, then merging them.

== Triggering

* *Automatic*: when `contextTokens > (contextWindow - reserveTokens)`. By default 16,384 tokens are reserved for the response.

* *Manual*: `/compact [instructions]` - optionally steer the summary, eg. `/compact focus on the API design decisions`.

== Settings

Configure under `compaction` in `~/.pi/agent/settings.json` or project-level `.pi/settings.json`:

[source,json]
----
{
  "compaction": {
    "enabled": true,
    "reserveTokens": 16384,
    "keepRecentTokens": 20000
  }
}
----

Set `"enabled": false` to disable auto-compaction; manual `/compact` still works.
