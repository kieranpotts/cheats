= Settings and context

== Configuration files

Pi reads two JSON settings files:

[cols="1,3", options="header"]
|===
| Location | Scope
| `~/.pi/agent/settings.json` | Global (all projects).
| `.pi/settings.json` | Project (current directory).
|===

Project settings override global ones via a nested merge. Project values replace
only the fields they define, leaving the rest of the global config intact.
Launch-time `--provider` / `--model` override both.

[source,json]
----
{
  "defaultProvider": "ollama-cloud",
  "defaultModel": "qwen3.5-coder:32b",
  "defaultThinkingLevel": "medium",
  "theme": "dark",
  "compaction": { "enabled": true, "reserveTokens": 16384, "keepRecentTokens": 20000 },
  "skills": ["../path/to/skills"]
}
----

== What you can configure

* Model and thinking: default provider/model, thinking level, token budgets.

* UI and display: theme, startup behavior, editor padding, autocomplete.

* Compaction: `reserveTokens`, `keepRecentTokens` — see
  link:./compaction.adoc[Compaction].

* Retry: error handling / exponential backoff.

* Shell: `shellPath`, `shellCommandPrefix`, npm commands.

* Resources: extensions, skills, prompts, themes - from packages or local paths.

* Terminal and images: image display and resizing.

== Project context (`AGENTS.md`)

Pi loads an `AGENTS.md` file in the project root at startup. Use this to define
project-specific rules, coding standards, or environment constraints:

[source,markdown]
----
# Project Instructions
- Run `npm run check` after code changes.
- Keep responses concise.
- Use functional programming patterns for new modules.
----

Run `/reload` inside Pi to refresh changes made to this file. See
link:./context.adoc[Context] for how `AGENTS.md` fits into the full
system-prompt stack.
