= Runtime modes

Pi has four execution modes:

* Interactive: the full TUI experience.

* Print/JSON: `pi -p "query"` runs the prompt and exits - useful for scripting. Add `--mode json` to emit a newline-delimited JSON event stream (session header, then agent / turn / message / tool / compaction events). Pipe to `jq` to filter.

* RPC: `pi --mode rpc` speaks JSONL over stdin/stdout for non-Node integrations (IDEs, custom UIs). Commands in (`prompt`, `steer`, `follow_up`, `set_model`, `get_state`, `new_session`, `fork`, ...), responses and an event stream out. An extension sub-protocol drives interactive dialogs.

* SDK: embed Pi in your own app - the best path for Node/TS. `createAgentSession()` returns an `AgentSession` with `prompt()`, `subscribe()`, and `setModel()`; `createAgentSessionRuntime()` handles new/switch/fork. OpenClaw is an example implementation.

[source,js]
----
const { session } = await createAgentSession({
  sessionManager: SessionManager.inMemory(),
  authStorage,
  modelRegistry,
});

session.subscribe((event) => {
  if (event.type === "message_update") {
    process.stdout.write(event.assistantMessageEvent.delta);
  }
});

await session.prompt("What files are in the current directory?");
----

== Scripting mode

The following script demonstrates how `pi -p` can be used in deterministic scripting to query LLMs.

This script iterates through a directory of Asciidoc files, used an LLM (via `pi`) to proofread them, make suggested edits, then commit the changes to a fresh branch and push the branch to GitHub and open a PR – one per file.

There are lots of safety procedures in place in this script. Pi's tools are restricted to read, edit, grep, find, and ls. No bash means the harness cannot physically run `git`, or push or delete anything. That part of the logic is kept in the deterministic script. The model is used solely for the things its good at: non-deterministic workflows like reasoning.

Two design points worth noting: `--no-session` gives each file a fresh, clean context so files don't contaminate each other, and the `git diff --quiet` check means files with no needed edits don't generate empty PRs.

[source,bash]
----
#!/usr/bin/env bash
set -euo pipefail

REPO_DIR="${1:?Usage: proofread.sh <repo-dir> [glob]}"
GLOB="${2:-**/*.adoc}"
BASE_BRANCH="${BASE_BRANCH:-main}"
MODEL="${MODEL:-anthropic/claude-sonnet}"   # adjust to a model from `pi --list-models`

cd "$REPO_DIR"
git checkout "$BASE_BRANCH"
git pull --ff-only

shopt -s globstar nullglob
for file in $GLOB; do
  echo "=== Proofreading: $file ==="
  branch="proofread/$(echo "$file" | tr '/.' '--')-$(date +%s)"
  git checkout -b "$branch" "$BASE_BRANCH"

  pi -p --no-session \
     --model "$MODEL" \
     --thinking low \
     --tools read,edit,grep,find,ls \
     "Proofread the AsciiDoc file at '$file' following AGENTS.md. Edit it in place. Touch no other file."

  if git diff --quiet -- "$file"; then
    echo "No changes; skipping."
    git checkout "$BASE_BRANCH"; git branch -D "$branch"; continue
  fi

  git add "$file"
  git commit -m "Proofread: $file"
  git push -u origin "$branch"
  gh pr create --base "$BASE_BRANCH" --head "$branch" \
     --title "Proofread $file" \
     --body "Automated proofreading edits for \`$file\`, generated by Pi. Review before merging."

  git checkout "$BASE_BRANCH"
done
----
