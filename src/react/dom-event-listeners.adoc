= DOM event listeners in React

React attaches event listeners declaratively. Pass a function to a prop named
`on` followed by the event name in camelCase, eg. `onClick`, `onChange`,
`onSubmit`, `onKeyDown`, or `onPointerEnter`.

[source,jsx]
----
export default function Example() {
  function handleClick() {
    console.log("I was clicked!")
  }

  function handleMouseOver() {
    console.log("I was hovered over!")
  }

  return (
    <div className="container">
      <img
        src="https://picsum.photos/640/360"
        alt="A random photo"
        onMouseOver={handleMouseOver}
      />
      <button onClick={handleClick}>Click me</button>
    </div>
  )
}
----

Pass the function itself. Don't call it.

[source,jsx]
----
/* ✅ Passes the function. React calls it on click. */
<button onClick={handleClick}>Save</button>

/* ✅ Wraps a call in an arrow function, to pass arguments. */
<button onClick={() => deleteItem(item.id)}>Delete</button>

/* ❌ Calls the function during render, and passes its return value. */
<button onClick={handleClick()}>Save</button>
----

Event handlers are the main place for side effects in React. Unlike rendering,
they don't need to be pure.

== The event object

React passes the handler a _synthetic event_. This wrapper has the same
interface as the browser's native event, including `target`, `currentTarget`,
`preventDefault()`, and `stopPropagation()`, and it behaves the same way in
every browser. The native event is available as `event.nativeEvent`.

[source,jsx]
----
function SearchForm() {
  function handleSubmit(event) {
    event.preventDefault()
    const query = new FormData(event.currentTarget).get("query")
    // …
  }

  return (
    <form onSubmit={handleSubmit}>
      <input name="query" />
    </form>
  )
}
----

== Propagation

Most events bubble up the React tree, from the element that fired them to its
ancestors. Call `event.stopPropagation()` to stop an event from reaching parent
handlers.

[source,jsx]
----
function Toolbar() {
  return (
    <div onClick={() => console.log("toolbar clicked")}>
      <button
        onClick={event => {
          event.stopPropagation()
          console.log("button clicked")
        }}
      >
        Play
      </button>
    </div>
  )
}
----

To handle an event in the capture phase, before it reaches its target, add
`Capture` to the prop name, eg. `onClickCapture`.

Since React 17, React attaches its listeners to the root container, not to
`document`. Events bubble through the React tree, not the DOM tree. An event
inside a portal therefore reaches the portal's React parents.

== Naming conventions

By convention, name handler functions `handle` followed by the event, eg.
`handleClick`. Name props that accept handlers `on` followed by the event, eg.
`onPlay`.

[source,jsx]
----
function PlayButton({ onPlay }) {
  return <button onClick={onPlay}>Play</button>
}

function App() {
  function handlePlay() {
    // …
  }

  return <PlayButton onPlay={handlePlay} />
}
----
