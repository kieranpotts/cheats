= React: Props

In React, components receive data from their parent components. This data is
passed as _props_.

The following example shows four instances of a `Contact` component. Each
receives different data via props, which are the equivalent of attributes on
native HTML elements.

[source,jsx]
----
function App() {
  return (
    <div className="contacts">
      <Contact
        img="./images/mr-whiskerson.png"
        name="Mr. Whiskerson"
        phone="(212) 555-1234"
        email="mr.whiskaz@catnap.meow"
      />
      <Contact
        img="./images/fluffykins.png"
        name="Fluffykins"
        phone="(212) 555-2345"
        email="fluff@me.com"
      />
      <Contact
        img="./images/felix.png"
        name="Felix"
        phone="(212) 555-4567"
        email="thecat@hotmail.com"
      />
      <Contact
        img="./images/pumpkin.png"
        name="Pumpkin"
        phone="(0800) CAT KING"
        email="pumpkin@scrimba.com"
      />
    </div>
  )
}
----

React passes all the props to the component as a single object, the first
argument of the function.

[source,jsx]
----
export default function Contact(props) {
  return (
    <div className="contact-card">
      <img src={props.img} alt="" />
      <h3>{props.name}</h3>
      <div className="info-group">
        <img src="./images/phone-icon.png" alt="Phone" />
        <p>{props.phone}</p>
      </div>
      <div className="info-group">
        <img src="./images/mail-icon.png" alt="Email" />
        <p>{props.email}</p>
      </div>
    </div>
  )
}
----

Alternatively, destructure the props in the function signature, into
individual variables.

[source,jsx]
----
export default function Contact({ img, name, phone, email }) {
  return (
    <div className="contact-card">
      <img src={img} alt="" />
      <h3>{name}</h3>
      <div className="info-group">
        <img src="./images/phone-icon.png" alt="Phone" />
        <p>{phone}</p>
      </div>
      <div className="info-group">
        <img src="./images/mail-icon.png" alt="Email" />
        <p>{email}</p>
      </div>
    </div>
  )
}
----

[TIP]
====
Both styles are common. Destructuring is the convention in the React docs. It
shows at a glance which props a component uses, and it is the only way to give
props default values in a function component. A single `props` object makes it
easier to tell props apart from other local variables.
====

Another common pattern applies to components that need a lot of props, like
this.

[source,jsx]
----
const cards = data.map(item => {
  return (
    <Card
      key={item.id}
      coverImg={item.coverImg}
      rating={item.rating}
      reviewCount={item.reviewCount}
      location={item.location}
      title={item.title}
      price={item.price}
      available={item.available}
    />
  )
})
----

Group the props into a single object instead.

[source,jsx]
----
const cards = data.map(item => {
  return (
    <Card
      key={item.id}
      item={item}
    />
  )
})
----

This pattern works particularly well with TypeScript, where an interface can
define the shape of the `item` object.

Alternatively, use the spread syntax to pass every property of the `item`
object as an individual prop.

[source,jsx]
----
const cards = data.map(item => {
  return (
    <Card
      key={item.id}
      {...item}
    />
  )
})
----

This needs no change to the `Card` component itself, only to the calling code.
The component ignores any props it doesn't use.

== Props versus attributes

The main difference between props and attributes is that props can hold _any_
JavaScript value, while HTML attributes are limited to strings.

To pass a value that isn't a string literal, wrap it in curly braces. React
evaluates the JavaScript expression inside, and passes the result as the prop.

[source,jsx]
----
<Joke
  punchline="..."
  isPun={true}
  upvotes={10}
  downvotes={2}
  comments={[{ author: "", body: "", title: "" }]}
/>
----

A prop with no value defaults to `true`, so `<Joke isPun />` is the same as
`<Joke isPun={true} />`.

== Default values

Give a prop a default value with a default parameter in the destructuring
pattern. The default applies when the prop is missing or `undefined`, but not
when it is `null`.

[source,jsx]
----
function Avatar({ person, size = 100 }) {
  return <img src={person.imageUrl} alt={person.name} width={size} />
}
----

[NOTE]
====
React 19 removed `defaultProps` for function components. Class components still
support it.
====

== The children prop

Content nested between a component's opening and closing tags arrives in the
special `children` prop. This lets a component wrap arbitrary content.

[source,jsx]
----
function Card({ children }) {
  return <div className="card">{children}</div>
}

function App() {
  return (
    <Card>
      <h2>Title</h2>
      <p>Body</p>
    </Card>
  )
}
----

== Forwarding props

Collect the remaining props with rest syntax, and spread them onto an inner
element. This lets callers set any native attribute on it.

[source,jsx]
----
function Button({ variant = "primary", ...rest }) {
  return <button className={`btn btn--${variant}`} {...rest} />
}

<Button type="submit" disabled>Save</Button>
----

Only spread props that the element understands. React warns about props that a
DOM element doesn't recognize, eg. `isActive`.

== Props are read-only

A component MUST NOT change its own props. When it needs to change something in
response to user input, it uses state instead. When the parent passes new props,
React re-renders the component with them.

== Refs as props

Since React 19, `ref` is a regular prop for function components.
