= React hooks: Transitions

By default, React treats every state update as _urgent_. Once it starts
rendering an update, it finishes before it handles anything else. If an
update triggers a slow render, the UI freezes until the render is done.

Imagine a page with three tabs: Home, Products, and About. The Products tab
renders thousands of items, and takes a second or two. If the user selects
Products and then immediately selects About, nothing happens until the
Products render finishes. Only then does React process the click on About.

[source,jsx]
----
import { useState } from "react"

function TabContainer() {
  const [tab, setTab] = useState("home")

  function selectTab(nextTab) {
    setTab(nextTab)
  }

  // …
}
----

A _Transition_ marks a state update as non-urgent. React renders it in the
background, and keeps the current UI on screen and responsive meanwhile. If a
more urgent update arrives, eg. a click or a keystroke, React interrupts the
Transition's render, handles the urgent update, and then starts the
Transition's render again with the latest state.

`useTransition`, introduced in React 18, returns two values.

* `isPending` is `true` while a Transition is in progress.

* `startTransition` takes a function, and marks every state update inside it as
  a Transition.

[source,jsx]
----
import { useState, useTransition } from "react"

function TabContainer() {
  const [tab, setTab] = useState("home")
  const [isPending, startTransition] = useTransition()

  function selectTab(nextTab) {
    startTransition(() => {
      setTab(nextTab)
    })
  }

  return (
    <>
      <TabButton onClick={() => selectTab("home")}>Home</TabButton>
      <TabButton onClick={() => selectTab("products")}>Products</TabButton>
      <TabButton onClick={() => selectTab("about")}>About</TabButton>
      <div style={{ opacity: isPending ? 0.6 : 1 }}>
        {tab === "home" && <HomeTab />}
        {tab === "products" && <ProductsTab />}
        {tab === "about" && <AboutTab />}
      </div>
    </>
  )
}
----

With this change, if the user selects Products and then immediately selects
About, React abandons the Products render, and renders About straight away.
Meanwhile, `isPending` dims the old tab, to show that new content is on its
way.

To start a Transition outside a component, or when you don't need
`isPending`, import `startTransition` directly from `react`.

[source,jsx]
----
import { startTransition } from "react"

startTransition(() => {
  setTab("products")
})
----

Since React 19.3, each Transition renders independently, so a slow Transition
no longer holds up unrelated ones.

== Async Transitions

_Changed in React 19._

Since React 19, the function passed to `startTransition` can be async. React
calls a function that runs in a Transition an _Action_. `isPending` stays
`true` until the whole async function has finished, and React applies its state
updates together at the end.

[source,jsx]
----
function UpdateName() {
  const [name, setName] = useState("")
  const [error, setError] = useState(null)
  const [isPending, startTransition] = useTransition()

  function handleSubmit() {
    startTransition(async () => {
      const error = await updateName(name)

      /* State updates after an `await` currently need their own
      `startTransition`, to stay part of the Transition. */
      startTransition(() => {
        if (error) {
          setError(error)
        } else {
          redirect("/path")
        }
      })
    })
  }

  return (
    <div>
      <input value={name} onChange={e => setName(e.target.value)} />
      <button onClick={handleSubmit} disabled={isPending}>Update</button>
      {error && <p>{error}</p>}
    </div>
  )
}
----

== Caveats

* Transitions don't make rendering faster. They lower its priority, so React can
  interrupt it to handle input. This improves Interaction to Next Paint (INP),
  but the slow render still costs the same.

* The function passed to `startTransition` runs straight away. React doesn't
  delay it. Only the state updates inside it are non-urgent.

* Don't use a Transition for the state of a controlled text input. The input
  must update urgently on each keystroke. Use `useDeferredValue` for the slow
  part of the UI instead.

* If a Transition throws an error, the nearest error boundary catches it.

* Updates in a Transition can animate with `<ViewTransition>`.

== Deferred values

`useDeferredValue(value)` is the other way to mark work as non-urgent. It
returns a copy of a value that can lag behind the original. On each update,
React first re-renders with the old deferred value, which is fast. It then
re-renders in the background with the new value, and abandons that render if
the value changes again first.

[source,jsx]
----
import { useDeferredValue, useState } from "react"

function SearchPage() {
  const [query, setQuery] = useState("")
  const deferredQuery = useDeferredValue(query)
  const isStale = query !== deferredQuery

  return (
    <>
      <input value={query} onChange={e => setQuery(e.target.value)} />
      <div style={{ opacity: isStale ? 0.5 : 1 }}>
        {/* Wrap SlowList in `memo` (or use the React Compiler) so that it
        skips re-rendering while `deferredQuery` is unchanged. */}
        <SlowList query={deferredQuery} />
      </div>
    </>
  )
}
----

The input stays responsive, because `query` updates urgently, while `SlowList`
catches up in the background.

Since React 19, `useDeferredValue(value, initialValue)` takes an optional
initial value. React uses it for the first render, then re-renders in the
background with `value`.

Use `useTransition` when you control the state update. Use `useDeferredValue`
when you only receive the value, eg. as a prop.
