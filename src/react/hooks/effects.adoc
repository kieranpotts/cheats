= React hooks: Effects

If you load the following component in a web UI, the console shows that the
component re-renders itself in an infinite loop.

[source,jsx]
----
import { useState } from "react"

export default function App() {
  const [starWarsData, setStarWarsData] = useState({})

  console.log("Component rendered")

  fetch("https://swapi.dev/api/people/1")
    .then(res => res.json())
    .then(data => setStarWarsData(data))

  return (
    <div>
      <pre>{JSON.stringify(starWarsData, null, 2)}</pre>
    </div>
  )
}
----

Why does this happen? The component renders initially with no data. When the
`fetch` resolves, it updates the component state, which triggers a re-render.
But the `fetch` code is at the top level of the component, so it runs again.
This is how React works: every render runs the component's top-level code
again.

So be careful about what you do in the top level of a component. Rendering
MUST be pure.

The solution is the `useEffect` Hook. It runs code that synchronizes a
component with an _external system_, after React has rendered the component and
updated the DOM. External systems include back-end services, browser APIs such
as `localStorage`, timers, and third-party widgets.

TIP: Think of Effects as _outside effects_. They let a component step outside
React and interact with other systems.

Here's the first part of the solution.

[source,jsx]
----
import { useEffect, useState } from "react"

export default function App() {
  const [starWarsData, setStarWarsData] = useState({})

  useEffect(() => {
    fetch("https://swapi.dev/api/people/1")
      .then(res => res.json())
      .then(data => setStarWarsData(data))
  })

  return (
    <div>
      <pre>{JSON.stringify(starWarsData, null, 2)}</pre>
    </div>
  )
}
----

The code that talks to the external system is now inside the Effect's callback
function. React runs it _after_ each render, rather than during it.

But there is still a problem. Each fetch updates the state, the state change
triggers a new render, and the new render runs the Effect again. The component
still loops forever.

== Dependencies

`useEffect` takes an optional second argument, an array of _dependencies_.
These are the reactive values (props, state, and variables declared in the
component) that the Effect reads. React runs the Effect after the first render,
and then again only when a dependency has changed since the last render. React
compares each dependency with its previous value using `Object.is`.

[cols="1,2"]
|===
|Dependencies |When the Effect runs

|None
|After every render.

|`[]`
|After the first render only.

|`[a, b]`
|After the first render, and after any render in which `a` or `b` changed.
|===

[source,jsx]
----
export default function App() {
  const [starWarsData, setStarWarsData] = useState({})

  useEffect(() => {
    fetch("https://swapi.dev/api/people/1")
      .then(res => res.json())
      .then(data => setStarWarsData(data))
  }, [])

  return (
    <div>
      <pre>{JSON.stringify(starWarsData, null, 2)}</pre>
    </div>
  )
}
----

In the following example, the first render fetches the Star Wars character with
ID 1. When the user clicks the button, the Effect fetches the next character,
with ID 2, and so on. The component prints the API response to the screen.

[source,jsx]
----
export default function App() {
  const [starWarsData, setStarWarsData] = useState({})
  const [num, setNum] = useState(1)

  useEffect(() => {
    fetch(`https://swapi.dev/api/people/${num}`)
      .then(res => res.json())
      .then(data => setStarWarsData(data))
  }, [num])

  return (
    <div>
      <button onClick={() => setNum(prevNum => prevNum + 1)}>
        Get Next Character
      </button>
      <pre>{JSON.stringify(starWarsData, null, 2)}</pre>
    </div>
  )
}
----

You don't choose the dependencies. The code of the Effect determines them, and
the `eslint-plugin-react-hooks` linter flags missing ones. To run an Effect
less often, change its code so that it reads fewer reactive values.

Objects and functions declared in the component are new on every render, so an
Effect that depends on one runs after every render. Create the object or
function inside the Effect instead, depend on its primitive parts, or memoize
it.

[source,jsx]
----
/* ❌ `options` is a new object on every render. */
const options = { serverUrl, roomId }
useEffect(() => {
  const connection = createConnection(options)
  connection.connect()
  return () => connection.disconnect()
}, [options])

/* ✅ Depends only on the primitive values. */
useEffect(() => {
  const connection = createConnection({ serverUrl, roomId })
  connection.connect()
  return () => connection.disconnect()
}, [serverUrl, roomId])
----

== Cleanup

Be careful about setting things up in Effects that may cause memory leaks.
Consider the following example.

[source,jsx]
----
export default function WindowTracker() {
  const [windowWidth, setWindowWidth] = useState(window.innerWidth)

  useEffect(() => {
    window.addEventListener("resize", function() {
      setWindowWidth(window.innerWidth)
    })
  }, [])

  return (
    <h1>Window width: {windowWidth}</h1>
  )
}
----

Instances of this component add a DOM event listener when they mount. But when
the component unmounts, the listener is not removed. This is a memory leak. To
fix it, return a _cleanup function_ from the Effect.

[source,jsx]
----
export default function WindowTracker() {
  const [windowWidth, setWindowWidth] = useState(window.innerWidth)

  useEffect(() => {
    function watchWindowWidth() {
      setWindowWidth(window.innerWidth)
    }

    window.addEventListener("resize", watchWindowWidth)

    return () => {
      window.removeEventListener("resize", watchWindowWidth)
    }
  }, [])

  return (
    <h1>Window width: {windowWidth}</h1>
  )
}
----

React runs the cleanup function before it runs the Effect again with new
dependencies, and when the component unmounts. Other things to clean up include
timers, subscriptions, and open connections, eg. to WebSockets.

*Every Effect that sets something up MUST clean it up.*

In development, Strict Mode mounts each component, unmounts it, and mounts it
again. So each Effect runs setup, then cleanup, then setup again. This exposes
Effects that are missing their cleanup. Don't suppress it with a ref that blocks
the second run. Fix the cleanup instead.

== Race conditions

When a dependency changes quickly, eg. as the user clicks "Get Next Character"
several times, the responses can arrive out of order. The component then shows
the data for an old request. To fix this, ignore the responses of stale
requests in the cleanup function.

[source,jsx]
----
useEffect(() => {
  let ignore = false

  fetch(`https://swapi.dev/api/people/${num}`)
    .then(res => res.json())
    .then(data => {
      if (!ignore) {
        setStarWarsData(data)
      }
    })

  return () => {
    ignore = true
  }
}, [num])
----

An `AbortController` does the same job, and also cancels the HTTP request.

[source,jsx]
----
useEffect(() => {
  const controller = new AbortController()

  fetch(`https://swapi.dev/api/people/${num}`, { signal: controller.signal })
    .then(res => res.json())
    .then(data => setStarWarsData(data))
    .catch(error => {
      if (error.name !== "AbortError") throw error
    })

  return () => controller.abort()
}, [num])
----

[NOTE]
====
Effects make a poor general-purpose data-fetching tool. They don't run on the
server, they start fetching only after the component renders, and they don't
cache the results. Prefer the data-fetching features of a framework, a library
such as TanStack Query or SWR, or the `use` API with Suspense.
====

== Effects with async functions

It may be tempting to make the Effect callback an async function.

[source,jsx]
----
export default function App() {
  // …

  useEffect(async () => {
    const res = await fetch(`https://swapi.dev/api/people/${num}`)
    const data = await res.json()
    setStarWarsData(data)
  }, [num])

  // …
}
----

Don't do this. An Effect callback may return a cleanup function, but an async
function always returns a promise. React can't run a promise as a cleanup
function.

Instead, define an async function inside the Effect, and call it. The Effect
can still return a cleanup function.

[source,jsx]
----
useEffect(() => {
  let ignore = false

  async function getMemes() {
    const res = await fetch("https://api.imgflip.com/get_memes")
    const data = await res.json()
    if (!ignore) {
      setAllMemes(data.data.memes)
    }
  }

  getMemes()

  return () => {
    ignore = true
  }
}, [])
----

== Stale closures

Each render creates new functions, and each function _closes over_ the props
and state of the render that created it. A function that outlives its render
keeps seeing those old values. This is a _stale closure_.

The classic example is an interval set up in an Effect that runs once.

[source,jsx]
----
function Counter() {
  const [count, setCount] = useState(0)

  useEffect(() => {
    const id = setInterval(() => {
      setCount(count + 1) // ❌ `count` is always 0, from the first render.
    }, 1000)
    return () => clearInterval(id)
  }, []) // The linter flags the missing `count` dependency.

  return <h1>{count}</h1>
}
----

The count goes to 1, and stays there. There are several fixes.

* *Use an updater function,* so the callback doesn't read the value at all.
  This is the best fix here.
+
[source,jsx]
----
setCount(c => c + 1)
----

* *Add the value to the dependencies,* so React sets the Effect up again with
  a fresh callback. Here, that would reset the interval on every tick.

* *Read the latest value from a ref,* for callbacks that must keep a stable
  identity.

* *Use an Effect Event,* for logic that an Effect fires but that shouldn't
  re-run the Effect.

Stale closures also affect `useCallback` and `useMemo` with missing
dependencies, and event handlers stored for later, eg. in a subscription.

== Effect events

_Added in React 19.2._

Sometimes an Effect needs the latest value of a prop or state variable, but
shouldn't re-run when that value changes. In the following example, the
Effect connects to a chat room. It should reconnect when `roomId` changes, but
not when `theme` changes.

`useEffectEvent` wraps the non-reactive part of the logic in an _Effect
Event_. An Effect Event always sees the latest props and state, and it is not a
dependency.

[source,jsx]
----
import { useEffect, useEffectEvent } from "react"

function ChatRoom({ roomId, theme }) {
  const onConnected = useEffectEvent(() => {
    showNotification("Connected!", theme)
  })

  useEffect(() => {
    const connection = createConnection(serverUrl, roomId)
    connection.on("connected", () => {
      onConnected()
    })
    connection.connect()
    return () => connection.disconnect()
  }, [roomId]) // ✅ Effect Events are not dependencies.

  // …
}
----

* Call Effect Events only from inside Effects.

* Declare an Effect Event in the same component or Hook as the Effect that uses
  it. Don't pass it to other components or Hooks.

* Don't use Effect Events to silence the dependency linter. Use them only for
  logic that is conceptually an event fired by the Effect.

== Layout effects

`useLayoutEffect` has the same API as `useEffect`, but React runs it after it
updates the DOM and before the browser paints. Use it to measure layout, eg. the
size of a tooltip, and to set state before the user sees the screen. It blocks
painting, so prefer `useEffect` for everything else.

Layout Effects don't run during server rendering. The server HTML shows the
component before the layout Effect has adjusted it, so the content can jump when
it hydrates.

== You might not need an Effect

Effects are an escape hatch, for synchronizing with systems outside React. Many
common uses of Effects are unnecessary.

* *Values calculated from props or state.* Calculate them during render. Use
  `useMemo` if the calculation is expensive.

* *Resetting state when a prop changes.* Pass a different `key` to the
  component.

* *Responding to a user event,* eg. sending a request when the user submits a
  form. Do this in the event handler, which knows what happened.

* *Notifying a parent of a state change.* Call the parent's callback in the
  same event handler that changes the state.

[source,jsx]
----
/* ✅ Calculated during render. */
const visibleTodos = todos.filter(t => !t.done)

/* ❌ An extra render, and two copies of the same data to keep in sync. */
const [visibleTodos, setVisibleTodos] = useState([])
useEffect(() => {
  setVisibleTodos(todos.filter(t => !t.done))
}, [todos])
----
