= React hooks: State

The following component renders a button labelled "Add Item" and a list of
items labelled "Thing 1" and "Thing 2". When the button is clicked, the
original array gets a new item, which the console log shows, but the list on
the page doesn't change.

[source,jsx]
----
function App() {
  const thingsArray = ["Thing 1", "Thing 2"]
  const thingsElements = thingsArray.map(thing => <p key={thing}>{thing}</p>)

  function addItem() {
    const newThingText = `Thing ${thingsArray.length + 1}`
    thingsArray.push(newThingText)
    console.log(thingsArray)
  }

  return (
    <div>
      <button onClick={addItem}>Add Item</button>
      {thingsElements}
    </div>
  )
}
----

There is nothing special about `thingsArray`. It is a local variable that
exists only while the component renders. React doesn't know that it changed,
so it doesn't re-render the component. On the next render, the variable starts
again from its initial value.

To make the component _reactive_, use the `useState` Hook. It returns an array
of two elements. The first is the current value of the state variable. The
second is a function that sets a new value, and tells React to re-render the
component.

[source,jsx]
----
import { useState } from "react"

function App() {
  const [things, setThings] = useState(["Thing 1", "Thing 2"])

  function addItem() {
    const newThingText = `Thing ${things.length + 1}`
    setThings(prevThings => [...prevThings, newThingText])
  }

  const thingsElements = things.map(thing => <p key={thing}>{thing}</p>)

  return (
    <div>
      <button onClick={addItem}>Add Item</button>
      {thingsElements}
    </div>
  )
}
----

== Using state setter functions

Consider the following component.

[source,jsx]
----
import { useState } from "react"

export default function App() {
  const [count, setCount] = useState(0)

  function add() {
    setCount(count++)
  }

  return (
    <div className="counter">
      <div className="counter--count">
        <h1>{count}</h1>
      </div>
      <button className="counter--plus" onClick={add}>+</button>
    </div>
  )
}
----

The `add()` function is wrong. `count` is a `const`, so `count\+\+` throws a
`TypeError`. Even with `let`, it would be wrong. It would assign to the local
variable, which React ignores, and the postfix `++` would pass the _old_ value
to `setCount`. Never assign to a state variable. Pass the next value to the
setter function instead.

[source,js]
----
function add() {
  setCount(count + 1)
}
----

When the next state depends on the previous state, you MAY pass an _updater
function_ instead of a value. React calls it with the pending state, and uses
its return value as the next state.

[source,jsx]
----
import { useState } from "react"

export default function App() {
  const [count, setCount] = useState(0)

  /* Long-form notation, for clarity: */
  // function add() {
  //   setCount(function (oldValue) {
  //     return oldValue + 1
  //   })
  // }

  function add() {
    setCount(prevCount => prevCount + 1)
  }

  function subtract() {
    setCount(prevCount => prevCount - 1)
  }

  return (
    <div className="counter">
      <button className="counter--minus" onClick={subtract}>–</button>
      <div className="counter--count">
        <h1>{count}</h1>
      </div>
      <button className="counter--plus" onClick={add}>+</button>
    </div>
  )
}
----

The difference matters when one event queues several updates. Each call to
`setCount(count + 1)` reads the same `count`, from the current render. Each
updater function receives the result of the one before it.

[source,jsx]
----
function addThree() {
  setCount(count + 1) // setCount(0 + 1)
  setCount(count + 1) // setCount(0 + 1)
  setCount(count + 1) // setCount(0 + 1), so `count` becomes 1
}

function addThree() {
  setCount(c => c + 1) // 0 => 1
  setCount(c => c + 1) // 1 => 2
  setCount(c => c + 1) // 2 => 3, so `count` becomes 3
}
----

Here's another example.

[source,jsx]
----
import { useState } from "react"

export default function App() {
  const [isGoingOut, setIsGoingOut] = useState(true)

  function changeMind() {
    setIsGoingOut(prevState => !prevState)
  }

  return (
    <div>
      <h1>Do I feel like going out tonight?</h1>
      <button onClick={changeMind}>
        {isGoingOut ? "Yes" : "No"}
      </button>
    </div>
  )
}
----

== State is a snapshot

Setting state doesn't change the variable in the code that is already running.
It asks React for a new render, and the new value arrives in that render.

[source,jsx]
----
function handleClick() {
  setCount(count + 1)
  console.log(count) // Still the old value.
}
----

React _batches_ state updates. It waits until all the code in an event handler
has run, then re-renders once with every update applied. Since React 18, this
also applies to updates in promises, timeouts, and native event handlers.

== Updating arrays and objects

Treat state as read-only. Don't mutate an array or object that is held in
state. Create an _entirely new_ array or object that includes the change, and
pass it to the setter. Spread syntax is the most convenient way to do this.

[source,jsx]
----
function App() {
  const [thingsArray, setThingsArray] = useState(["Thing 1", "Thing 2"])

  function addItem() {
    setThingsArray(prevThingsArray => {
      return [
        ...prevThingsArray,
        `Thing ${prevThingsArray.length + 1}`
      ]
    })
  }

  const thingsElements = thingsArray.map(thing => <p key={thing}>{thing}</p>)

  return (
    <div>
      <button onClick={addItem}>Add Item</button>
      {thingsElements}
    </div>
  )
}
----

The non-mutating array methods return new arrays, and suit state updates.

* *Add.* `[...arr, item]`
* *Remove.* `arr.filter(x => x.id !== id)`
* *Replace.* `arr.map(x => x.id === id ? { ...x, done: true } : x)`
* *Sort.* `arr.toSorted(compareFn)`, or copy first with `[...arr].sort()`

To update a property of an object in state, replace the _whole_ object.

[source,jsx]
----
const [contact, setContact] = useState({
  firstName: "John",
  lastName: "Doe",
  phone: "+1 (719) 555-1212",
  email: "itsmyrealname@example.com",
  isFavorite: true
})

let starIcon = contact.isFavorite ? "star-filled.png" : "star-empty.png"

function toggleFavorite() {
  setContact(prevContact => {
    return {
      ...prevContact,
      isFavorite: !prevContact.isFavorite
    }
  })
}

return (
  <img
    src={`../images/${starIcon}`}
    className="card--favorite"
    alt="Favorite"
    onClick={toggleFavorite}
  />
)
----

[NOTE]
====
Class components update state with the `this.setState()` method, which behaves
differently from the `useState` setter. `setState` takes an object with a
subset of the state's properties, and merges it into the current state. The
`useState` setter replaces the whole value.
====

== Initializing state lazily

React calls `useState` on every render, but uses the initial value only on the
first render. An expensive expression in the argument still runs every time.

[source,jsx]
----
const [notes, setNotes] = useState(
  JSON.parse(localStorage.getItem("notes")) || []
)
----

To avoid this, pass an _initializer function_ instead of a value. React calls
it only on the first render.

[source,jsx]
----
const [notes, setNotes] = useState(
  () => JSON.parse(localStorage.getItem("notes")) || []
)
----

== Props vs state

*Props* are values that a parent component passes into a component, like
arguments passed into a function. Another way to think about props is that
they _configure_ a component. Props are read-only. A component MUST NOT change
its own props.

*State* is data that a component _manages itself_, and which changes over
time, eg. in response to user input. Each change goes through the setter
function, never by mutation. When state changes, React re-renders the
component. This is what sets state apart from props and plain local variables.

Props MAY be used to set some initial (default) state in a component. And state
MAY be passed as props to child components.

When a component re-renders, React also re-renders all its child components by
default, whether or not their props changed. Use `memo`, or the React Compiler,
to skip children whose props haven't changed.

In the following example, the `App` component is the parent component, and the
`Count` component is the child component. When `count` changes in the `App`
component, the `Count` component re-renders.

.App.jsx
[source,jsx]
----
import { useState } from "react"
import Count from "./Count"

export default function App() {
  const [count, setCount] = useState(0)

  function add() {
    setCount(prevCount => prevCount + 1)
  }

  function subtract() {
    setCount(prevCount => prevCount - 1)
  }

  console.log("App component rendered")

  return (
    <div className="counter">
      <button className="counter--minus" onClick={subtract}>–</button>
      <Count number={count} />
      <button className="counter--plus" onClick={add}>+</button>
    </div>
  )
}
----

.Count.jsx
[source,jsx]
----
export default function Count(props) {
  console.log("Count component rendered")

  return (
    <div className="counter--count">
      <h1>{props.number}</h1>
    </div>
  )
}
----

Child components can change the parent's state by calling functions that the
parent passes down as props.

.Parent
[source,jsx]
----
function App() {
  const [contact, setContact] = useState({
    // …
    isFavorite: true
  })

  function toggleFavorite() {
    setContact(prevContact => ({
      ...prevContact,
      isFavorite: !prevContact.isFavorite
    }))
  }

  return (
    <main>
      {/* … */}
      <Star isFilled={contact.isFavorite} handleClick={toggleFavorite} />
      {/* … */}
    </main>
  )
}
----

.Child
[source,jsx]
----
function Star(props) {
  const starIcon = props.isFilled ? "star-filled.png" : "star-empty.png"
  return (
    <img
      src={`../images/${starIcon}`}
      className="card--favorite"
      alt="Favorite"
      onClick={props.handleClick}
    />
  )
}
----

== Best practices for managing component state

Keep state as local as possible. Put each piece of state in the closest common
parent of the components that need it, _but no higher_. Moving state up to a
common parent is called _lifting state up_.

Avoid *redundant state*. If a value can be calculated from props or other state
during render, calculate it, rather than storing it in state. There is then
nothing to keep in sync.

[source,jsx]
----
/* ✅ Calculated during render. */
const fullName = firstName + " " + lastName

/* ❌ Stored in state, and must be kept in sync by hand. */
const [fullName, setFullName] = useState("")
----

Don't *mirror props in state*. In the following example, the `Box` (child)
component receives the `on` prop, which sets the background color of the box.
Clicking the box toggles the color. Each `Box` copies the prop into its own
state.

[source,jsx]
----
function Box(props) {
  /* Local state initialized from a prop. */
  const [on, setOn] = useState(props.on)

  const styles = {
    backgroundColor: on ? "#222222" : "transparent"
  }

  function toggle() {
    setOn(prevOn => !prevOn)
  }

  return (
    <div style={styles} className="box" onClick={toggle}></div>
  )
}
----

This works, but now there are two sources of truth. The state ignores later
changes to the `on` prop, because React uses the initial value only on the
first render. Better to keep _one source of truth_ for each piece of state. The
`on` value comes from the parent component, so the parent should manage changes
to it, and pass the result back down.

[source,jsx]
----
function Box(props) {
  const styles = {
    backgroundColor: props.on ? "#222222" : "transparent"
  }

  /* The parent component defines `toggle` and passes it down as a prop. This
  lets the parent change its own state in response to events in the child. To
  pass a value back to the parent, wrap the call in another function. */
  return (
    <div
      style={styles}
      className="box"
      onClick={() => props.toggle(props.id)}
    >
    </div>
  )
}

export default function App() {
  const [squares, setSquares] = useState(boxes)

  function toggle(id) {
    setSquares(prevSquares => {
      return prevSquares.map(square => {
        return square.id === id ? { ...square, on: !square.on } : square
      })
    })
  }

  const squareElements = squares.map(square => (
    /* `key` is a special prop that React uses to track list items between
    renders. React doesn't pass it to the component, so `props.key` is always
    `undefined`. Pass a separate `id` prop if the child needs the value. */
    <Box
      key={square.id}
      id={square.id}
      on={square.on}
      toggle={toggle}
    />
  ))

  return (
    <main>
      {squareElements}
    </main>
  )
}
----

Alternatively, the parent can create a separate callback for each `<Box>`,
with the `id` of the box already bound inside it. The child then calls the
callback with no arguments.

[source,jsx]
----
/* App.jsx */
<Box
  key={square.id}
  on={square.on}
  toggle={() => toggle(square.id)}
/>

/* Box.jsx */
<div
  style={styles}
  className="box"
  onClick={props.toggle}
>
</div>
----

This is the better pattern. The parent creates the `id` values for its own
internal logic, and that detail no longer leaks out to the child.

== Resetting state with a key

React keeps a component's state as long as the same component renders at the
same position in the tree. To reset the state, give the component a different
`key`. React then treats it as a new component, and mounts it with fresh state.

[source,jsx]
----
/* Clears the draft message whenever the user switches to another contact. */
<Chat key={contact.id} contact={contact} />
----
