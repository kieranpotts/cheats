= React hooks: Actions

_Added in React 19._

An _Action_ is a function that runs inside a _Transition_, and can be async.
While an Action runs, React tracks its pending state, keeps the current UI
interactive, and shows optimistic updates. When the Action finishes, React
applies its state updates together. If the Action throws, the nearest
error boundary catches the error.

You create Actions in the following ways.

* Pass a function to `startTransition`.

* Pass a function to an _action prop_, eg. the `action` prop of `<form>`, or
  the `formAction` prop of `<button>`. React wraps the call in a Transition for
  you.

* Call the dispatch function returned by `useActionState`.

== Form actions

Before React 19, to submit a form you used an `onSubmit` handler. It called
`event.preventDefault()`, and then updated the state based on the form data.

[source,jsx]
----
import { useState } from "react"

function App() {
  const [input, setInput] = useState("")
  const [name, setName] = useState(
    () => JSON.parse(localStorage.getItem("name")) || ""
  )

  function handleChange(event) {
    setInput(event.target.value)
  }

  async function handleSubmit(event) {
    event.preventDefault()
    try {
      const newName = await updateNameInDb(input)
      setName(newName)
      setInput("")
    } catch (error) {
      console.error(error.message)
    }
  }

  return (
    <>
      <p>Your name is: {name}</p>
      <form onSubmit={handleSubmit}>
        <input
          type="text"
          value={input}
          onChange={handleChange}
          required
        />
        <button type="submit">Update</button>
      </form>
    </>
  )
}
----

In React 19, you can pass a function to the form's `action` prop instead. React
calls it with the form's `FormData` object.

React builds on the web platform here. The `action` attribute is native to
HTML `<form>` elements, where it takes the URL to which the browser sends the
form data. React also accepts a function.

In the following refactored code, the input no longer needs state. The input
manages its own value, as an uncontrolled input, and the action reads it from
the `FormData`. After the action succeeds, React resets the form.

[source,jsx]
----
import { useState } from "react"

function App() {
  const [name, setName] = useState(
    () => JSON.parse(localStorage.getItem("name")) || ""
  )

  async function formAction(formData) {
    try {
      const newName = await updateNameInDb(formData.get("name"))
      setName(newName)
    } catch (error) {
      console.error(error.message)
    }
  }

  return (
    <>
      <p>Your name is: {name}</p>
      <form action={formAction}>
        <input
          type="text"
          name="name"
          required
        />
        <button type="submit">Update</button>
      </form>
    </>
  )
}
----

This removes much of the boilerplate that form handling needed before. But the
component still has no pending or error state. Before React 19, these needed
yet more state variables.

[source,jsx]
----
function App() {
  const [name, setName] = useState(
    () => JSON.parse(localStorage.getItem("name")) || ""
  )
  const [loading, setLoading] = useState(false)
  const [error, setError] = useState(null)

  async function formAction(formData) {
    setLoading(true)
    setError(null)
    try {
      const newName = await updateNameInDb(formData.get("name"))
      setName(newName)
    } catch (error) {
      console.error(error.message)
      setError(error)
    } finally {
      setLoading(false)
    }
  }

  // …
}
----

== useActionState

`useActionState` manages state that an Action updates.

[source,js]
----
const [state, dispatchAction, isPending] = useActionState(
  reducerAction,
  initialState,
  permalink // Optional.
)
----

* `reducerAction(previousState, payload)` is the Action. It receives the
  current state, and the value passed to `dispatchAction`. Its return value
  becomes the new state. It can be sync or async.

* `initialState` is the state before the first dispatch.

* `permalink` is the URL of the page the form modifies. It is for forms that
  submit to a server function before the JavaScript bundle has loaded.

The Hook returns three values.

* `state` is the current state.

* `dispatchAction` runs the Action. Pass it to a form's `action` prop, or call
  it inside `startTransition`.

* `isPending` is `true` while any dispatched Action is in progress.

The following code refactors the previous example with `useActionState`.

[source,jsx]
----
import { useActionState } from "react"

async function updateNameAction(prevState, formData) {
  try {
    const name = await updateNameInDb(formData.get("name"))
    return { name, error: null }
  } catch (error) {
    return { ...prevState, error: error.message }
  }
}

function App() {
  const [state, formAction, isPending] = useActionState(updateNameAction, {
    name: "",
    error: null,
  })

  return (
    <>
      <p>Your name is: {state.name}</p>

      {isPending && <p>Loading…</p>}

      <form action={formAction}>
        <input
          type="text"
          name="name"
          required
        />
        <button type="submit" disabled={isPending}>Update</button>
        {!isPending && state.error && <p>{state.error}</p>}
      </form>
    </>
  )
}
----

The Action handles expected errors itself, by returning them as part of the
state. The component then has complete control over how it renders them.
Errors that the Action throws go to the nearest error boundary instead.

When a form calls `dispatchAction`, the Action receives the `FormData` as its
payload. Outside a form, call `dispatchAction` inside `startTransition`, and
pass it any payload.

[source,jsx]
----
import { startTransition, useActionState } from "react"

function Checkout() {
  const [count, dispatchAction, isPending] = useActionState(
    updateCartAction,
    0
  )

  function handleAdd() {
    startTransition(() => {
      dispatchAction({ type: "ADD" })
    })
  }

  // …
}

async function updateCartAction(prevCount, action) {
  switch (action.type) {
    case "ADD":
      return await addToCart(prevCount)
    case "REMOVE":
      return await removeFromCart(prevCount)
  }
  return prevCount
}
----

* React queues dispatched Actions, and runs them one after another. Each Action
  receives the state that the previous one returned.

* `dispatchAction` has a stable identity, so Effects don't need it as a
  dependency.

* `useActionState` was briefly called `useFormState`, and imported from
  `react-dom`, in React's canary releases. `useFormState` is deprecated.

== Resetting a form

React resets a form automatically after its action succeeds. To reset a form at
another time, call `requestFormReset(formElement)`, from `react-dom`, inside a
Transition.
