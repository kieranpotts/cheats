= Production builds

Browsers can't run JSX, and a large app is made of many modules. A production
React app therefore needs a build step that compiles JSX, bundles the modules,
and minifies the output.

The React docs recommend starting new apps with a framework. Where no framework
fits, use a build tool such as Vite, Parcel, or Rsbuild.

[WARNING]
====
Create React App (`create-react-app`) was deprecated in 2025-02. Don't use it
for new apps. Migrate existing apps to a framework or a build tool.
====

== Frameworks

A framework adds routing, data fetching, server rendering, and support for
server components.

[cols="1,1"]
|===
|Framework |Command

|Next.js (App Router)
|`npx create-next-app@latest`

|React Router (framework mode)
|`npx create-react-router@latest`

|Expo (native apps)
|`npx create-expo-app@latest`
|===

== Vite

Vite compiles JSX and bundles the app. It also has a development server with
hot module replacement (HMR). To scaffold a new project, run the following.

[source,bash]
----
npm create vite@latest my-app -- --template react
cd my-app
npm install
npm run dev
----

Use `--template react-ts` for TypeScript. Run `npm create vite@latest` with no
arguments to choose a template from a menu, including templates with the React
Compiler turned on.

The template defines the following scripts.

* `npm run dev` starts the development server.

* `npm run build` writes an optimized production build to `dist/`.

* `npm run preview` serves `dist/` locally, to test the production build.

The entry point is `index.html`. Its `<script>` tag points at the source code.
Vite compiles the code on the fly in development, and points the tag at the
bundled output when it builds.

.index.html
[source,html]
----
<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>Bob's Bistro</title>
  </head>
  <body>
    <div id="root"></div>
    <script type="module" src="/src/main.jsx"></script>
  </body>
</html>
----

.src/main.jsx
[source,jsx]
----
import { StrictMode } from "react"
import { createRoot } from "react-dom/client"
import "./index.css"
import App from "./App"

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <App />
  </StrictMode>
)
----

=== Static assets

Import images and other assets so the bundler can include them in the build,
with a content hash in the file name. The import resolves to the URL of the
processed file.

[source,jsx]
----
import logo from "./assets/logo.png"

function Header() {
  return (
    <header>
      <nav>
        <img src={logo} alt="Bob's Bistro" />
      </nav>
    </header>
  )
}
----

Vite copies files in the `public/` directory to the build as they are. Refer to
them by absolute path, eg. `<img src="/favicon.svg" alt="" />`.

=== CSS

Import CSS files from JavaScript, too. A file named `*.module.css` is a CSS
module. Vite scopes its class names to the importing component, so they can't
clash with class names elsewhere.

[source,jsx]
----
import "./main.css"
import styles from "./Button.module.css"

function Button() {
  return <button className={styles.primary}>Save</button>
}
----

=== Environment variables

Vite exposes environment variables prefixed with `VITE_` on `import.meta.env`.
It also sets `import.meta.env.DEV` and `import.meta.env.PROD`.

[source,js]
----
const apiUrl = import.meta.env.VITE_API_URL
----

[WARNING]
====
Vite embeds these values in the JavaScript sent to the browser. Never put
secrets in `VITE_` variables.
====

== Development and production builds of React

React ships a development build, with extra warnings and checks, and a faster,
smaller production build without them. Build tools pick the right one based on
the mode, so `npm run build` always uses the production build.
